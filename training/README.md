# حزمة بيانات تدريب Harb

هذه المجلدات مخصصة لإعداد بيانات مؤسسية **مرخصة ومراجعة فقط**. لا تبدأ تجربة ضبط دقيق عند إنشاء هذه الملفات؛ بل بعد تعبئة سجل البيانات، مراجعة الحقوق، فصل المجموعات، ومرور حالات الاختبار المحجوبة.

يعتمد Harb على نماذج أساس جاهزة؛ راجع `BASE_MODEL_STRATEGY.md` لاختيار المرشح وتقييمه قبل التفكير في أي تخصيص محدود.

## التسلسل المطلوب

| الخطوة | الملف | شرط القبول |
| --- | --- | --- |
| تسجيل المصدر | `data-manifest.template.json` | مصدر وحقوق وتصنيف ومراجعة مسجلة لكل مجموعة |
| توصيف المثال | `instruction-record.schema.json` | لا أسرار، ولا بيانات شخصية غير مصرح بها، ولا تفاصيل تشغيلية هجومية |
| فصل المجموعات | حقل `split` في السجل | تدريب/تحقق/اختبار من دون تداخل أو تسرب |
| التقييم المحجوب | `evaluation-case.schema.json` | مرجع قرار ومقياس وحدود سلامة لكل حالة |
| قرار التجربة | سجل النموذج في Harb | توقيع مراجعة بشرية وقياسات خط أساس |

> لا تضع نصوص المؤسسة أو أي ملفات حساسة في هذا المستودع. احتفظ بالبيانات الأصلية في مساحة تخزين المالك المحمية، وسجّل هنا المخططات والبيانات الوصفية فقط.

يوجد سجل المراجع العامة في `data-manifest.json`، وتفصيل شروطها وقرارات استخدامها في `PUBLIC_REFERENCE_REGISTER.md`. استخدم `node validate-dataset.mjs <records.jsonl>` قبل إدخال أي سجل إلى تجربة. تفحص الأداة الحقوق، مراجعة السلامة، بيانات الأسرار أو البيانات الشخصية المعلنة، وأنماطاً حساسة، والتكرار أو التشابه المرتفع بين تقسيمات البيانات.

تصف `TRAINING_EXECUTION_PLAN.md` شروط تجربة الضبط الدقيق في بيئة GPU منفصلة، بينما يحدد `run-metadata.schema.json` و`model-card.template.md` ما يجب توثيقه لكل تجربة وإصدار.

أنشئ ميتاداتا تجربة فقط بعد اعتماد البيانات عبر:

```bash
pnpm training:prepare-run --records /مسار/records.jsonl --output /مسار/run.json --model نموذج-أساس-مرخص --method lora --approval مرجع-موافقة-المالك
```

لا يشغّل هذا الأمر تدريباً أو يستدعي GPU؛ إنما يرفض السجلات المخالفة وينتج خطة تجربة قابلة للتدقيق. لا يبدأ منفذ التدريب في بيئة GPU إلا بعد اعتماد هدف الحوسبة وحقوق البيانات من المالك.

لتقييم نماذج الأساس على حالات محجوبة ومعتمدة، استخدم:

```bash
pnpm training:baseline --cases /مسار/cases.jsonl --models gpt-5-mini,gpt-5 --output /مسار/baseline-report.json
```

يفحص المنفذ حالة المراجعة وأنماط الأسرار قبل استدعاء أي نموذج، ويسجل دقة القرار ومعدل القرار الآمن لكل نموذج. لا تشغّله على مراجع أو بيانات لم تعتمد حقوقها.

قبل نقل تجربة الضبط الدقيق إلى بيئة GPU، استخدم `training:readiness` مع سجل البيانات وتقرير الأساس وملف هدف GPU المعتمد. يرفض الفاحص الانتقال عند غياب مراجعة المالك أو حقوق التدريب أو تقرير المقارنة أو ضوابط التشفير والوصول.

ابدأ من `gpu-target.template.json` وراجعه مقابل `gpu-target.schema.json`. لا يحدد Harb مزوداً أو منطقة أو بطاقة GPU نيابة عن المالك؛ لأنها قرارات ترتبط بالميزانية، إقامة البيانات، واتفاقيات المؤسسة.

راجع `GPU_REQUIREMENTS.md` لمواصفات الذاكرة والتخزين والأمن الشبكي قبل اعتماد هدف الحوسبة.
