# خطة تنفيذ ضبط دقيق Harb

## قرار البنية

لا يبدأ Harb بتدريب نموذج أساسي من الصفر. المسار الأول هو **ضبط دقيق محدود** أو تخصيص موفر للمعلمات لنموذج أساس مرخص، بعد إثبات أن الاسترجاع المقيد وتحسين التعليمات لا يعالجان خطأً منتظماً في المهام المؤسسية. يظل خادم Harb مسؤولاً عن الحوكمة والسجل والتقييم، بينما يجري التدريب الفعلي في بيئة GPU منفصلة ومصرح بها.

## مواصفات التجربة الأولى

| العنصر | القاعدة |
| --- | --- |
| نوع التحسين | تجربة LoRA/QLoRA أو بديل موفر للمعلمات يدعمه نموذج الأساس المرخص |
| البيانات | سجلات اجتازت `training:validate` ولها حقوق ومراجعة بشرية مكتملة |
| حجم البداية | أصغر عينة كافية لإثبات الفرضية، لا تجميع شامل للمراجع العامة |
| التقسيم | تدريب/تحقق/اختبار محجوب مع فحص تكرار وتسرب قبل التشغيل |
| المقارنة | النموذج الأساسي مع الإعدادات نفسها وقانون المالك والاسترجاع ذاته |
| السلامة | قياس الرفض الآمن وحالات التفويض الناقص وعدم إنتاج تعليمات تشغيل غير مفوضة |
| الإيقاف | إيقاف التجربة عند تراجع المقياس أو فشل بوابة السلامة أو ظهور بيانات غير مصرح بها |

## البيئة المطلوبة

تحتاج التجربة الفعلية إلى بيئة GPU يمكن التحكم بها، وتخزين مشفر، ومسار وصول ضيق للبيانات، وسجل حزم وإصدارات، ومكان لحفظ نقاط التحقق. لا تضع البيانات أو نقاط التحقق في مستودع الويب. تظل أدوات Harb الحالية مناسبة للتحضير، التحقق، التقييم، وحفظ البيانات الوصفية؛ وليست بديلاً عن بيئة تدريب GPU.

## تسلسل التشغيل

1. يراجع المالك `data-manifest.json` ويعتمد مصادر وأمثلة محددة، لا المراجع كاملة بصورة عامة.
2. يشغّل الفريق `pnpm training:validate <dataset.jsonl>` ويسجل النتيجة وحزمة التجزئة.
3. ينفذ خط الأساس على الحالات المحجوبة ويثبت وجود فجوة قابلة للقياس.
4. يشغّل تجربة ضبط دقيقة صغيرة في بيئة GPU منفصلة، مع حفظ `run-metadata` و`model-card`.
5. يقارن النتائج ويطلب مراجعة بشرية قبل استخدام أي نقطة تحقق داخل المؤسسة.

## شروط عدم النشر

لا ينشر نموذج معدل إذا لم تتوفر حقوق البيانات، أو كانت مجموعة الاختبار غير محجوبة، أو لم يتحسن المقياس المحدد، أو تراجعت حالات الرفض الآمن، أو تعذر توثيق الإصدار والبيانات والإعدادات.
